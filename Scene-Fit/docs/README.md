# Scene Fit Frontend

MCM SCENE FIT의 프론트엔드 앱입니다. 기획·기능 명세는 저장소 루트 [README.md](../../README.md), 백엔드 계약은 [API.md](./API.md)를 참고하세요.

> 현재 단계: **P0 화면 흐름 완료 / Carry Check 완료 / P1 수납 시각화 완료 / Fit Pass 완료 / 백엔드 연동 / 장면 시각화 연결 / 착용 미리보기·카탈로그 정리**  
> 기준일: 2026-08-21

---

## 현재 개발 정도

제품 선택 → 착용 미리보기 → 조건 입력(위저드) → Fit Check 결과 → 비교 → Store Fit Pass까지 **P0 화면 흐름은 연결**되어 있습니다. 카탈로그·미리보기·이후 단계는 SCENE FIT 카탈로그 헤더(뒤로 + 로고, MCM 워드마크 없음)로 맞춰 두었습니다.

Scene Fit Card의 Carry Check는 가방 공식 수납·치수와 소지품 스펙(크기 프리셋 포함)을 대조해 4단계 배지와 수납 지표 점수를 보여 줍니다. 결과 화면에서는 선택한 소지품을 가방 안에 **2D 단면 / 3D 실루엣**으로 옮겨 볼 수 있습니다.

착용 미리보기는 공식 제품 컷을 사람(실루엣 또는 업로드 사진) 위에 올리고, 키 입력으로 실제 치수 비율을 맞춥니다. `/preview`에서 착용 위치 칩(토트·숄더·롱스트랩·크로스바디·백팩)으로 올린 뒤 **드래그로 미세 조정**합니다. 끈을 SVG로 그리지 않고 공식 이미지를 그대로 씁니다.

결과 화면(`/result`)은 장소/시기를 넣으면 백엔드가 장면 배경을 만들고, 이 기기에서 사람을 오려 그 뒤에 깔 수 있습니다. 장면 문구·장소 뱃지·지도 링크는 배경 합성과 따로 붙습니다. 마스크가 없으면 올린 사진 배경이 그대로 남습니다.

백엔드는 `VITE_API_BASE_URL`로 카탈로그·세션·Fit Check·추천·Fit Pass·장면 배경을 호출하고, 실패하거나 `VITE_API_MOCK=true`이면 로컬 데이터·규칙 엔진으로 이어갑니다. 장면 생성은 목업 모드에서는 호출하지 않습니다.

## Carry Check Engine

`/result` Scene Fit Card — 가방 스펙(공식 수납 품목, 가로/세로/폭)과 선택한 소지품 스펙을 대조합니다. 서버가 있으면 `POST /fit-check` 결과를 쓰고, 없거나 실패하면 `src/lib/itemFit.ts` · `src/lib/fitCheck.ts` 로컬 규칙으로 이어갑니다. 휴대전화·태블릿·노트북·보조배터리는 `src/data/itemPresets.ts` 크기를 쓰면 그 치수로 다시 판정합니다. 대표 프리셋이 아니면 공식 확인(`confirmed`)을 주지 않습니다.

| 단계 | 배지 | 기준 |
| --- | --- | --- |
| 확인됨 (`confirmed`) | 🟢 | `officialStorage`에 해당 품목이 있음. 치수 추측으로 뒤집지 않음 |
| 예상됨 (`estimated`) | 🔵 | 축 정렬 회전 후 가장 빡센 축 점유율 ≤ 85% |
| 매장 확인 필요 (`store-check`) | 🟡 | 점유율 85% 초과 ~ 100% 이하 (입구·셰이프·유연성 경계) |
| 어려움 (`unlikely`) | 🔴 | 점유율 100% 초과 (가방 AABB를 넘김) |

수납 지표 점수는 품목 점수의 평균입니다. 확인됨 100 / 예상됨 80 / 매장 확인 50 / 어려움 0. 소지품이 없으면 점수를 숨깁니다. 결과 카드에는 점수(`/100`)와 품목별 배지·점유율을 붙이고, 비교 화면에도 같은 4단계 태그를 씁니다.

## 수납 시각화

`/result` — Carry Check 아래 **가방 안에 옮겨 보기**. 판정 엔진과 별도로, 선택한 소지품을 공식 치수 박스 안에 배치합니다.

| 항목 | 내용 |
| --- | --- |
| 3D (기본) | 정면 컷으로 몸통 실루엣, 옆면 컷으로 깊이. Three.js로 회전·드래그 |
| 2D | 정면 단면. 넓은 물건은 앞면이 크게 보임. 겹침은 앞뒤 적재일 수 있음 |
| 자동 배치 | AABB 축 정렬 6방향, 간격 6mm (`src/lib/packLayout.ts`) |
| 조작 | 드래그 이동, 탭으로 회전, 기기 크기 프리셋 변경, 다시 맞추기 |
| 상태 | 가방 밖 / 부피 겹침 / 안에 있음 카운트 |
| 한계 | 실제 형태·재질 유연성은 반영하지 않음. 수납 **판정**은 Carry Check가 담당 |

## 착용 미리보기 상세

`/preview` — **내 사진 올리기** / **실루엣으로 보기**

### 구현된 것

| 항목 | 내용 |
| --- | --- |
| 입력 전환 | 전신 사진 업로드·카메라 촬영 ↔ 키·체형·성별 실루엣 아바타 (기본 여성) |
| 촬영 가이드 | 카메라에 실루엣 오버레이. “정면으로, 팔 내린 채” 안내 |
| 비율 공식 | `공식 치수 : 내 키 = 화면 가방 : 사진(또는 실루엣) 속 키` |
| 제품 이미지 | 목록·미리보기 모두 공식 컷 그대로. 끈을 SVG로 그리지 않음 |
| 정면 컷 보정 | 손잡이·스트랩이 포함된 세로 컷은 사진 비율로 상자를 잡아, 가방 가로가 공식 너비에 맞게 보임 |
| 온디바이스 분석 | MediaPipe Pose Landmarker + segmentation (사진 서버 미전송) |
| 픽셀 키 | 사람 마스크 위~아래 우선, 없으면 관절(머리~발) 보조 |
| 가방 배치 | 착용 위치 칩으로 어깨·손·허리·등에 올린 뒤 드래그로 이동. 백팩은 사람 뒤에 배치(정면 기준) |
| 자세 경고 | 어깨·엉덩이가 안 보이거나 팔을 들었을 때 다른 사진을 권함 |
| 사진 비율 | 업로드 이미지 원본 가로·세로 비율 유지 (`object-fit: contain`) |
| 모드 전환 | 사진/실루엣 가방 크기 분리 저장 — 왕복 시 크기 유지 |
| 실루엣 접지 | 발 기준으로 바닥에 붙임. 가방 선택 시 떠 보이지 않게 맞춤 |
| 안내 | 키 조절 시 가방 비율이 바뀌는 이유 도움말, 매장 확인 디스클레이머 |

조건 입력 위저드의 착용 방식은 미리보기 칩과 같은 `wearStyle`을 씁니다. 제품 데이터에 `hasLongStrap`(공식 상세의 긴 어깨 스트랩 여부)이 있으면 미리보기에 롱스트랩 칩이 추가됩니다.

### 의도적으로 하지 않는 것

- 생성형 AI로 **나를 다시 그리거나 가방을 재생성**하는 것 (AI 인물 엔드포인트는 남아 있으나 기본값에서 뺌)
- 공식 이미지에 없는 끈을 그려 넣는 것
- 사진만으로 실제 cm 키를 추정하는 것 (사용자가 **내 키** 입력)

### 남은 개선 후보

1. 반신·앉은 자세·뒷모습에서 배경 합성이 자주 스킵되는 안내를 더 분명히
2. 뒷모습일 때 백팩을 사람 앞에 두기
3. 비율이 어색할 때만 쓰는 선택적 미세 조절(±)

## 장면 시각화

`/result` — 조건의 **장소/시기**(예: 도쿄여행)가 있을 때 장면 카드와 미리보기를 맞춥니다. `useSceneVisual` → `POST /scene/background`.

| 항목 | 내용 |
| --- | --- |
| 장면 생성 | 백엔드 OpenAI가 배경 이미지 + 컨셉 문구 + 장소 이름을 만듦. 프론트에 OpenAI 키 없음 |
| 화면 카피 | 목적지 · 컨셉(예: Tokyo Indoor Explorer) · 장소 뱃지 · 지도에서 보기 · 바꾸기 |
| 사진 합성 | 사람 마스크가 있으면 원본 배경을 생성 장면으로 교체. 컷아웃 톤을 장면 밝기에 맞춤 |
| 발밑 그림자 | 원본 사진에 붙은 바닥 그림자·가짜 접지 타원·아래 비네팅을 걷어 냄 |
| 실루엣 | 사진이 없으면 생성 배경 위에 실루엣만 세움 (마스크 불필요) |
| 로딩 | 15~20초 걸릴 수 있어 `SceneProgress` 표시 |
| 목업 | `VITE_API_MOCK=true`이거나 목적지가 비면 생성하지 않음 |

장면 문구·지도는 사람 오려붙이기와 **따로** 붙습니다. 서버가 장소 이름을 내려줘도, 이 기기에서 마스크를 못 만들면 올린 사진 배경(야구장 등)이 그대로 남습니다. 정면 전신에서 가장 잘 되고, 뒷모습·반신·복잡한 배경에서는 자세만 읽고 합성은 건너뛰는 경우가 많습니다.

## Store Fit Pass

매장에 “이 제품을 보여 주세요”가 아니라, 확인하고 싶은 질문을 전달합니다. 실시간 재고·예약 확정은 하지 않습니다.

| 항목 | 내용 |
| --- | --- |
| 입력 | 희망 매장(4곳 목업), 방문 시간(선택), 체험 목적, 직접 확인할 항목 |
| 신청 위치 | `/fit-pass` 전용 화면, `/result`·`/compare` 모달 |
| 완료 화면 | 디지털 티켓(제품·매장·체험·확인 항목, QR·바코드 장식) |
| 상태 데모 | `요청` → `확인 중` → `확인 완료`. 서버 접수 시 발급 ID를 쓰고, 목업이면 로컬 타임라인 |

## 화면 흐름

```
홈
 ├─ 궁금한 가방이 있어요 → /products → /preview → /conditions → /result → /compare → /fit-pass
 ├─ 어떤 가방이 맞을지 모르겠어요 → /recommend → (제품 선택 후 동일)
 └─ 60초 빠른 체험 → /result (데모 데이터)
```

홈을 제외한 카탈로그·미리보기·조건·결과·비교·Fit Pass는 SCENE FIT 카탈로그 헤더(뒤로 + 로고)를 씁니다. 결과·비교 화면에서도 Fit Pass 모달로 바로 신청할 수 있습니다.

| 경로 | 화면 |
| --- | --- |
| `/` | 홈·진입 |
| `/products` | 제품 선택 |
| `/preview` | 2D 착용 미리보기 |
| `/conditions` | 장면·조건 입력 |
| `/result` | Scene Fit Card + 장면 미리보기 + 수납 시각화 |
| `/compare` | 대안 비교 |
| `/fit-pass` | Store Fit Pass |
| `/fit-pass/done` | 요청 완료(디지털 티켓) |
| `/recommend` | 조건 기반 추천 |

## 시작하기

```bash
cp .env.example .env
npm install
npm run dev
```

| 명령              | 설명               |
| ----------------- | ------------------ |
| `npm run dev`     | 개발 서버 실행     |
| `npm run build`   | 프로덕션 빌드      |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run lint`    | ESLint 검사        |

`.env`는 커밋하지 않습니다. 로컬은 `VITE_API_BASE_URL=/v1`와 `VITE_API_PROXY_TARGET`으로 백엔드를 붙입니다. Vercel에는 `VITE_API_BASE_URL=https://mcm-scene-fit-be.vercel.app/v1`처럼 **빌드 타임** 값을 넣습니다. 서버 없이 보려면 `VITE_API_MOCK=true`. **OpenAI 키는 프론트 `.env`에 넣지 않습니다** — 장면 배경은 백엔드가 만듭니다.

착용 미리보기 첫 분석 시 MediaPipe 모델·WASM을 CDN에서 받습니다. **인터넷 연결**이 필요하며, 추론 자체는 기기에서 실행됩니다.
